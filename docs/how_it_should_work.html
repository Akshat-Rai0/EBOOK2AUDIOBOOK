How Castbook should work

Behaviour, from file drop to finished audiobook.

Analogy

Think of a radio-play studio. The script editor marks who says each line, the casting director picks an actor per role, the actors record their lines, and the sound engineer stitches them into chapters.

Flow

  1. Import. User picks a file. Text and chapter titles are extracted and cleaned (page numbers, headers, hyphenation).
  2. Split. Book becomes chapters, chapters become chunks that fit the LLM context, cut at paragraph edges.
  3. Attribute. The local LLM turns each chunk into segments with a speaker. It receives the known cast so far, so names stay consistent.
  4. Cast. Aliases merge into one character. Voices are auto-suggested (gender, age hint, frequency of speech). The user can review and change them.
  5. Speak. Each segment is synthesised with its character's voice. Long segments are cut to the engine's limit.
  6. Assemble. Add short pauses, level loudness, join per chapter, write the m4b with chapter markers.

Example (invented text)

Input:  Mira set the lamp down. "You lied to me," she said. "I did not," Tomas answered.
Output: [narrator] Mira set the lamp down.
        [Mira]     You lied to me,
        [narrator] she said.
        [Tomas]    I did not,
        [narrator] Tomas answered.

Rules

  • Dialogue tags ("she said") go to the narrator.
  • Unknown speaker: label unknown, fall back to narrator voice, list it for review. Never guess silently.
  • Thoughts and letters read aloud: narrator by default, switchable per character.
  • Every LLM output is validated as JSON. Invalid output is retried, then falls back to narrator.
  • Each finished segment is cached, so re-runs are cheap.

Modes

Narrator-only: skips attribution, one voice, runs on the low-resource floor. Multi-voice: the full pipeline.
